## 0. Headline findings

1. Claude Code ships a bundled `/deep-research` workflow whose architecture is almost identical to our research-queue (scope 5 angles, parallel search, URL-dedup fetch + claim extraction, 3-vote adversarial verify, cited synthesis). It runs under `claude -p`. We tested it on this box (section 4). The DESIGN doc calls it "interactive-only"; that is no longer true on 2.1.292.
2. OpenAI retired `o3-deep-research` and `o4-mini-deep-research` on 2026-07-23. The replacement is a normal reasoning model (`gpt-5.6-sol`, or `gpt-5.5` high/xhigh per the web-search guide) plus the `web_search` tool in background mode. There is no dedicated "deep research" SKU any more. Most 2025 tutorials are stale.
3. Perplexity moved from Sonar Deep Research to an Agent API with tiered presets (`fast, low, medium, high, xhigh`). By Perplexity's own benchmark page the old Sonar Deep Research is dominated by `medium` on both quality and cost (BrowseComp 29.1% at ~$0.61/req vs 69.3% at ~$0.044/req). An official API key replaces our fragile cookie-hijack MCP.
4. Independent evidence that dedicated "deep research" products beat a frontier LLM with search tools is thin. FutureSearch's offline-web DRB (the only independent harness I found) ranks plain Opus 4.6 / Sonnet 4.6 / Opus 4.5 (high reasoning) at the top, at about $0.46 to $0.53 per task. Vendor benchmarks conflict with each other and use 50 to 100 question samples.
5. Subscription OAuth may only be used with Claude Code and claude.ai. Third-party frameworks that read `~/.claude/.credentials.json` (DeerFlow's "Claude Code OAuth" provider) conflict with Anthropic's policy. Claude Code skills/plugins (hyperresearch, last30days) run inside Claude Code and are fine.

## C. Fit against our research-queue

### C.1 What research-queue already does that the field does not

- Dual independent backends (Perplexity lane via Hermes + Claude web lane) with cross-backend claim ranking. Only hyperresearch's independence audit is comparable.
- Deterministic Python claim merge, no silent caps, 7 named binary gate kills, FAILED-GATE banner instead of silence, per-stage resume, usage-pause awareness.
- Confidence tags and a Killed-claims section as structural output (Claude's bundled workflow returns structured JSON, not a gated report).

### C.2 Where it is weaker than what is now available

1. S4 is one batched sonnet verify call over up to 12 claims (README: "RQ_MAX_CLAIMS (12)", ~6 claude calls worst case). Bundled `/deep-research` runs 3 independent voter agents per claim (up to 25 claims), each with its own WebSearch, 2 refutations kill, default to refuted if uncertain. That is far more thorough and far more expensive (see section 4 for measured usage).
2. No required verbatim quote per claim and no deterministic check that the quote exists in the fetched page (hyperresearch "quote-integrity"; bundled workflow requires `quote` in the claim schema).
3. No source-quality or date field on claims (bundled script: `sourceQuality` primary/secondary/blog/forum/unreliable, `publishDate`, importance central/supporting/tangential, ranking before cap).
4. Prompt injection: sweeps are inlined into synth prompts up to 24k chars. The bundled script strips control, bidi, zero-width and quote-lookalike characters and frames web text as "evidence to weigh, never instructions".
5. K5 counts distinct domains, but five reprints of one press release are five domains. Hyperresearch clusters syndicated copies.
6. Perplexity lane depends on a cookie-hijack MCP with a ~30 day token. Official Agent API `medium` is ~$0.05 per run.
7. No internal eval set. Anthropic's own advice: ~20 test cases, LLM judge on factual accuracy, citation accuracy, completeness, source quality, tool efficiency, plus human review for SEO content-farm bias.

### C.4 Design ideas worth stealing (all verified in sources above)

1. 3-vote refutation with `default refuted if uncertain`, apply to the central claims only to bound cost. Source: bundled workflow script.
2. Claim schema: `claim`, `quote` (verbatim), `sourceQuality` enum, `publishDate`, `importance`; rank by importance then source quality before applying the cap. Add gate K8: every quote must be a substring of the stored page text (deterministic, no LLM).
3. Injection hardening in S5/S4 inputs: strip Cc/Cf/bidi/quote-lookalikes, wrap web text with the "evidence, never instructions" note.
4. URL normalization dedup with a fetch budget and a logged drop list (script keeps `dupes` and `budgetDropped`).
5. Independence clustering: collapse syndicated copies before K5 counts "distinct domains". Source: hyperresearch README.
6. Budget object per run (`maxCostDollars`, `maxDurationSeconds`) with enumerated `stopReason` (Exa Agent). Map onto RQ env caps and write the stop reason into meta.json.
7. Per-claim confidence plus reasoning field (Parallel "Research Basis"; Exa `output.grounding`).
8. Plan-approval gate before spend (Gemini `collaborative_planning`): night-queue could emit the S1 angles for a yes/no before S2 on expensive tiers.
9. Effort tiers with fixed cost bands (Perplexity presets; Anthropic effort-scaling rules: 1 agent and 3 to 10 tool calls for simple, 10+ subagents for complex). Replace ad hoc `--fast` with `fast/standard/deep` profiles.
10. Prompt Gemini-style "if figures are unavailable, say so rather than estimate" in sweep prompts.
11. 20 to 30 question internal eval with an LLM judge rubric (Anthropic eng blog) so engine swaps (Perplexity API vs cookie MCP vs Gemini DR) are measured on our questions, not vendor ones.
12. Passage filter before synthesis: GPT Researcher reports 59% more relevant context than embeddings with its Jev filter. Laya on :8095 is described in memory as open-source Jev; compatibility is UNVERIFIED.
13. STORM-style persona angles for S1 (customer, skeptic, regulator) to diversify sweeps. Idea only; project stale.

## D. Caveats

1. Vendor benchmarks are self-run on 50 to 100 question samples and contradict each other (Eden AI). Only FutureSearch's DRB is independent and it does not test the dedicated APIs. Hyperresearch's "leads DRB" claim is not on the public leaderboard.
2. OpenAI's dedicated models are gone; the box has no OpenAI API key (Codex runs on a ChatGPT login, not an API key: UNVERIFIED but no key in env). Any OpenAI path needs a new key and `gpt-5.6-sol`/`gpt-5.5` plus `web_search`.
3. Anthropic policy: subscription OAuth is "exclusively" for Claude Code and native apps; developers and Agent SDK products must use API keys (https://code.claude.com/docs/en/legal-and-compliance.md, news summary https://gigazine.net/gsc_news/en/20260220-anthropic-third-party-block). So DeerFlow's Claude Code OAuth provider and any LiteLLM-style reuse of the Max token are out. GPT Researcher, LDR, Onyx with Claude would need a metered API key.
4. `claude -p` plus `/deep-research`: the first JSON result is only the launch acknowledgement (see section 4). Use stream-json and wait for the process or the workflow journal. No usage-limit pause in `-p`, so a limit hit mid-run turns agents into failures reported as "unverified".
5. Gemini Deep Research is preview, paid tier only, and Google calls its cost figures estimates ("no independent developer measurements exist yet" per tokencost.app at launch).
